    • 1同步的痛点：一条队伍排到底

    顺风耳能同时听见千里之外的所有动静——但你现在写的 Python 还是「单线程同步」模式：一次只做一件事，前一件没做完，后一件就得排队。

    最烧钱的场景是IO 等待：下载文件、请求网页、读写数据库。这些事的特点是——发出请求后，CPU 只能干等对方响应，等的不是你的电脑，而是网络和硬盘。

    🗺 下载地图3 秒（其中约 3 秒在干等 💤）
    🎵 下载音效3 秒（干等 💤）
    🎨 下载皮肤3 秒（干等 💤）
    同步串行：3 + 3 + 3 = 9 秒，而 CPU 真正干活的时间可能不到 0.1 秒

    用最普通的写法复现一下：

    import time def download(name): print("开始下载", name) time.sleep(3) # 模拟 3 秒的下载等待：整个程序原地卡住 print("完成", name) download("地图") download("音效") download("皮肤")
    开始下载 地图 完成 地图 开始下载 音效 完成 音效 开始下载 皮肤 完成 皮肤

    🧠 记住这个痛点：同步模式下，「等待」也在占用你的程序。如果一次要下载 100 个文件，就得排队 300 秒——而异步，能把这 300 秒压到约 3 秒。

    2协程：async def 与 await

    异步的主角是协程（coroutine）：一种「可以中途暂停、把时间让给别人、之后再回来继续」的函数。定义它只需在 def 前面加一个 async：

    import asyncio async def fetch_treasure(): # async def：定义协程函数 print("开始寻宝") await asyncio.sleep(2) # await：等待时把控制权交出去 print("寻宝完成") return "黄金宝箱" async def main(): box = await fetch_treasure() # await：等协程跑完并拿结果 print("得到：", box) asyncio.run(main()) # 启动事件循环，运行 main
    开始寻宝 寻宝完成 得到： 黄金宝箱

    两条黄金规则：

    ① 调用协程函数 ≠ 执行它。fetch_treasure() 只是返回一份「任务说明书」（协程对象），必须交给 await 或事件循环才会真正运行。

    ② await = 等待结果 + 让出时间。它一边等结果，一边告诉调度员：「我先歇着，你让别人先跑」——这就是异步省时间的全部秘密。

    3事件循环：一位忙碌的调度员

    事件循环（event loop）是异步世界的中枢调度员。它手里攥着所有任务，规则只有一条：谁进入等待，就立刻切去推进别的任务，绝不让 CPU 闲着。

    🗺 任务 A
    await 等待中 💤
    ⚙ 事件循环
    调度员：切换！切换！
    谁等待就让位
    🎵 任务 B
    await 等待中 💤
    🎨 任务 C
    await 等待中 💤

    看上面的动效：粉色高亮像调度员一样在三个任务间轮转——其实同一时刻只有一个任务在真正运行

    asyncio.run(main()) 就是「把调度员请上台」的指令：创建事件循环 → 运行 main 协程 → 结束后关闭。整个程序通常只调用它一次。

    ⚠️ 但调度员有个天敌：time.sleep()。它是阻塞式等待——直接把整个事件循环按住动弹不得：

    async def main(): time.sleep(3) # 💥 假异步！事件循环被卡死 3 秒，所有任务排队干等 await asyncio.sleep(3) # ✅ 真异步：等待 3 秒，期间调度员随便切换

    🧠 记忆口诀：协程里要等，一律 await asyncio.sleep()，别碰 time.sleep()。

    4gather 并发 · 选型 · 两大新手坑

    单个 await 还是串行。真正让时间重叠的，是把多个协程一起交给调度员——用 asyncio.gather 并发收集：

    import asyncio, time async def download(name): print("开始下载", name) await asyncio.sleep(3) # 异步等待：把时间让给别人 print("完成", name) async def main(): start = time.time() await asyncio.gather( download("地图"), download("音效"), download("皮肤"), ) print("总耗时：", round(time.time() - start, 1), "秒") asyncio.run(main())
    开始下载 地图 开始下载 音效 开始下载 皮肤 完成 地图 完成 音效 完成 皮肤 总耗时： 3.0 秒

    注意输出顺序：三个「开始下载」先全部出现——每个任务一进入 3 秒等待，调度员立刻切换去启动下一个；三段等待重叠进行，所以总耗时 ≈ 最慢的那一个（3 秒），而不是 9 秒。

    异步还是多线程？选型口诀：

    · 大量 IO 并发（爬虫、API、聊天服务器）→ 首选 asyncio：单线程协作式调度，没有锁竞争，轻松扛成千上万个连接，是现代 Python 的主流选择。

    · CPU 密集型计算（图像处理、大规模运算）→ asyncio 帮不上忙，用多进程。threading 适合少数量的简单 IO 并发或调用阻塞库。

    最后是两大新手坑，几乎人人踩过：

    💥 坑一：忘记 await。只拿到协程对象，代码根本没执行：

    async def fetch(): return 42 value = fetch() # 💥 少写了 await！ print(value)
    <coroutine object fetch at 0x10393de40> RuntimeWarning: coroutine 'fetch' was never awaited

    地址每次都不同，但看到 coroutine object 就说明：你拿的是说明书，不是宝物。改成 await fetch() 即可。

    💥 坑二：await 写错了地方。await 只能出现在 async def 函数体内，写进普通函数或函数外都会直接 SyntaxError：

    def normal(): await asyncio.sleep(1) # 💥 SyntaxError: 'await' outside async function

    切换点：任务一进入等待，事件循环立刻切去启动下一个任务

    刚才的动画，对应这两份真实代码（可直接在电脑上运行验证）：

    # ① 同步版：排队 9 秒 import time def download(name): print("开始下载", name) time.sleep(3) print("完成", name) for task in ["地图", "音效", "皮肤"]: download(task)
    开始下载 地图 完成 地图 开始下载 音效 完成 音效 开始下载 皮肤 完成 皮肤
    # ② gather 版：并发 3 秒（注意输出顺序） import asyncio async def download(name): print("开始下载", name) await asyncio.sleep(3) print("完成", name) async def main(): await asyncio.gather( download("地图"), download("音效"), download("皮肤"), ) asyncio.run(main())
    开始下载 地图 开始下载 音效 开始下载 皮肤 完成 地图 完成 音效 完成 皮肤
    📊 计时对比：同步版 9.0 秒 ｜ gather 版 3.0 秒 —— 并发数越多，差距越夸张（100 个任务：300 秒 vs 约 3 秒）。异步不是让下载变快，而是让「等待」彼此重叠。
