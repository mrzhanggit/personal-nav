    • 1什么是 API：餐厅点餐的智慧

    你的程序想要的"情报"——天气、汇率、排行榜——都存放在别人的服务器上。程序怎么拿到手？靠 API（Application Programming Interface，应用程序接口）。

    把整个过程想象成在餐厅点餐：

    🧑
    你 = 程序
    客户端，负责点菜
    — — ➤
    🤵
    服务员 = API
    接收需求、传达后厨、端回结果
    — — ➤
    👨‍🍳
    厨房 = 服务器
    真正做菜（处理数据）的地方
    点击按钮，看一份情报是怎么被"端"回来的……

    关键理解：你不需要知道厨房怎么炒菜，只要按菜单（API 文档）正确点菜，就能拿到做好的菜（数据）。翻译成 Python 只需要几行：

    import requests # 情报小哥模块（pip install requests 安装） # api.example.com 是演示用地址，真实项目里要填接口文档给的完整地址 r = requests.get("api.example.com/v1/weather", params={"city": "杭州"}) data = r.json() # 把返回的 JSON 情报拆成字典

    这一课的所有代码都围绕这四行展开。注意：requests 不是内置模块，第一次用要先在终端执行 pip install requests。

    2requests.get() 与 Response：情报回执单

    requests.get(地址) 会向服务器发出 GET 请求，返回一个 Response 对象——一张"回执单"，上面记着状态码、返回内容等所有信息：

    import requests r = requests.get("api.example.com/v1/weather", params={"city": "杭州"}) print(type(r)) print(r.status_code)
    <class 'requests.models.Response'> 200

    回执单上最重要的字段是 r.status_code（状态码），它告诉你这次点餐的结果。三个最常见的号码：

    200
    OK · 成功
    菜上齐了！服务器成功返回了数据
    404
    Not Found · 找不到
    菜单上没这道菜：地址写错或资源不存在
    500
    Server Error · 服务器错误
    厨房着火了！问题出在服务器那边

    🧠 记忆口诀：2xx 成功、4xx 你的锅（地址/权限）、5xx 服务器的锅。养成习惯：拿到 r 先看 status_code，不是 2xx 就别急着解析数据。

    3r.text 与 r.json()：生肉与装盘

    服务器返回的原始内容是一整段字符串。你可以选择"生吃"（r.text），也可以让 requests 帮你"装盘"（r.json()）：

    🥩 r.text —— 生肉（原始字符串）

    类型是 str，内容原封不动，想取某个字段得自己切字符串，非常痛苦：

    data = r.text # '{"city": "杭州", "temp": 26.5, ...}' # 一整段文字，没法 data["temp"]

    🍽️ r.json() —— 装盘（解析好了）

    把 JSON 自动解析成 Python 的 dict / list，直接用方括号取字段：

    data = r.json() data["temp"] # 26.5 data["city"] # '杭州'
    import requests r = requests.get("api.example.com/v1/weather", params={"city": "杭州"}) print(type(r.text)) # 原始内容：一整段字符串 print(type(r.json())) # 解析后：字典（若接口返回数组则是列表）
    <class 'str'> <class 'dict'>

    假设接口返回的 JSON 原文长这样（注意：JSON 里的键和字符串都用双引号）：

    { "city": "杭州", "temp": 26.5, "weather": "多云" }

    用 r.json() 解析后，就像操作普通字典一样取字段：

    data = r.json() print(data["city"]) print(data["temp"]) print(data["weather"])
    杭州 26.5 多云

    ⚠️ 想取的键不存在会抛 KeyError——不确定有没有时，用 data.get("键") 兜底，取不到返回 None 而不是报错。

    4params：把需求写在订单上

    查杭州天气、查北京天气，接口地址只有 city 这一处不同。把变化的部分交给 params 参数（一个字典），不用自己手动拼地址：

    import requests url = "api.example.com/v1/weather" r = requests.get(url, params={"city": "北京", "lang": "zh"}) print(r.status_code) # params 会被自动拼接到地址问号后面，相当于： # .../v1/weather?city=北京&lang=zh（中文会被自动转码，无需操心）
    200

    问号后面的 ?city=北京&lang=zh 叫查询字符串。手拼字符串容易漏转义、写错符号，交给 params 既安全又省事——这也是"服务员帮你传话"的意义。

    5超时、异常与 API Key：情报员的自我修养

    网络会断、服务器会卡。一个不设防的请求可能让程序干等几十秒甚至直接崩溃。专业做法是三件套：timeout + try/except + raise_for_status：

    import requests try: r = requests.get("api.example.com/v1/weather", params={"city": "杭州"}, timeout=5) r.raise_for_status() # 状态码不是 2xx 就主动抛异常 data = r.json() print(data["weather"]) except requests.Timeout: print("请求超时，请稍后再试") except requests.RequestException: print("请求失败：网络异常或地址有误")

    三个要点：timeout=5 表示最多等 5 秒；超时会抛 requests.Timeout 异常；except 的顺序要把更具体的 Timeout 放在更宽泛的 RequestException 前面（子类在前）。

    最后一条红线：API Key 的保密意识。很多 API 需要"通行证"（API Key）才能调用，而 key 一旦泄露，别人就能冒充你刷你的额度：

    import os import requests # ❌ 危险写法：key 写死在代码里，一旦提交到代码仓库就等于公开 # api_key = "sk-1234567890abcdef" # ✅ 安全写法：从环境变量读取，代码里根本见不到 key 本体 api_key = os.environ.get("WEATHER_API_KEY") r = requests.get("api.example.com/v1/weather", params={"city": "杭州"}, headers={"Authorization": "Bearer " + str(api_key)})

    🧠 记住三不要：不写死在代码里、不提交到仓库、不截图发群里。key 泄露了要立刻去平台重置。
