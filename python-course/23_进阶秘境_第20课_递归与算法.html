    • 1递归三要素 —— 自己解决自己

    递归就是函数在体内调用自己。听起来像套娃，其实像「走迷宫」：把大岔路丢给「下一个自己」，直到撞到出口。每个能活下来的递归函数，都缺不了三样东西：

    ① 基线条件
    出口
    到这一步直接返回，不再调用自己
    ② 递归条件
    缩小问题
    每次调用都离出口更近一步
    ③ 自我调用
    调用自己
    函数体内出现自己的名字

    经典入门例子——火箭倒数：

    def countdown(n): if n == 0: # ① 基线条件：到 0 就发射 print("🚀 发射！") else: countdown(n - 1) # ②③ 问题缩小 + 自我调用 countdown(3)
    🚀 发射！

    调用链条是这样一层层「钻」进去的：

    countdown(3) → countdown(2) → countdown(1) → countdown(0) → 命中出口，打印「🚀 发射！」

    ⚠️ 最常见的灾难：忘了写基线条件（或者问题没在缩小），函数会无限调用自己，直到撞上递归深度限制当场爆炸——第 4 节带你亲眼看。

    2阶乘 —— 把大问题敲碎

    阶乘：5! = 5×4×3×2×1 = 120。它天然适合递归，因为 n! = n × (n-1)!——大问题里藏着一个一模一样的小问题：

    def factorial(n): if n == 1: # ① 基线条件：1! 就是 1 return 1 return n * factorial(n - 1) # ②③ 缩小问题 + 自我调用 print(factorial(5))
    120

    把递归「展开再收回」的过程画出来，一眼就懂：

    factorial(5) = 5 × factorial(4) = 5 × 4 × factorial(3) = 5 × 4 × 3 × factorial(2) = 5 × 4 × 3 × 2 × factorial(1) ← 撞到基线，返回 1 = 5 × 4 × 3 × 2 × 1 = 120

    先一层层压进去（等待），再一层层弹回来（计算）。实验室的沙盘 A 会把这个压栈 / 弹栈过程演给你看。

    3斐波那契 —— 重复计算的炸弹

    斐波那契数列：1, 1, 2, 3, 5, 8……规则是 fib(n) = fib(n-1) + fib(n-2)。递归写法优雅得像诗：

    def fib(n): if n < 2: # 基线：fib(0)=0，fib(1)=1 return n return fib(n - 1) + fib(n - 2) # 一个问题裂成两个子问题 print(fib(4))
    3

    但优雅背后藏着炸弹——「裂成两个」意味着调用树疯狂分叉，同一个子问题被反复重算：

    fib(4) ├─ fib(3) │ ├─ fib(2) │ │ ├─ fib(1) ✓ │ │ └─ fib(0) ✓ │ └─ fib(1) ✓ └─ fib(2) ├─ fib(1) ✓ └─ fib(0) ✓ fib(2) 算了 2 次，fib(1) 算了 3 次，fib(0) 算了 2 次 → 仅仅算 fib(4) 就调用了 9 次！

    规模一大就彻底失控：算 fib(35) 要调用 2986 万次函数，多数是纯浪费的重复劳动。解药是缓存——算过的存表，下次直接查（这正是上一课 @lru_cache 附魔的主场）：

    from functools import lru_cache @lru_cache(maxsize=None) # 缓存附魔：算过的直接查表 def fib(n): if n < 2: return n return fib(n - 1) + fib(n - 2) print(fib(35)) # 2986 万次调用 → 36 次，瞬间出结果
    9227465

    4悬崖与护栏 —— 深度限制 & 递归 vs 循环

    Python 不允许无限套娃。每递归一层就占用一帧调用栈，栈有上限，默认约 1000 层：

    import sys print(sys.getrecursionlimit()) # 查看当前最大递归深度
    1000

    如果递归没有出口，超限的瞬间就是这个名场面：

    def boom(n): return boom(n + 1) # 没有基线条件：一路挖到地心 boom(1)
    💥 RecursionError: maximum recursion depth exceeded

    其实任何递归都能改写成循环（阶乘的循环版）：不占调用栈、没有深度限制、通常更快——

    def factorial_loop(n): result = 1 for i in range(2, n + 1): # 从 2 一路乘到 n result *= i return result print(factorial_loop(5))
    120

    那什么时候非递归不可？问题天然分叉的时候——迷宫回溯、汉诺塔、文件目录遍历这类「每条岔路都要试」的问题，递归写出来清清爽爽，硬用循环反而要手工维护一个栈。经验法则：线性累加用循环，天然分叉用递归。

    5二分查找 —— 每次砍掉一半

    在 100 根武器里找「攻击力 73」的那根：挨个翻是笨办法；聪明的做法是站在有序队伍正中间问一句「你比 73 大还是小？」——一句话砍掉 50 人。这就是二分查找，前提只有一个：序列必须有序。

    def binary_search(data, target): low, high = 0, len(data) - 1 # 搜索区间的两端 while low <= high: mid = (low + high) // 2 # 站到正中间 if data[mid] == target: return mid # 命中，返回下标 elif data[mid] < target: low = mid + 1 # 目标在右半，砍掉左半 else: high = mid - 1 # 目标在左半，砍掉右半 return -1 # 没找到 nums = [2, 5, 8, 12, 16, 23, 38, 56, 72, 91] print(binary_search(nums, 23)) # 23 在下标 5 print(binary_search(nums, 100)) # 不存在，返回 -1
    5 -1

    找 23 只用了 3 步：mid=4（16 偏小）→ mid=7（56 偏大）→ mid=5（命中）！挨个找最坏要翻 10 次。数据越大差距越夸张：100 万个有序数，二分查找最多约 20 步。

    6大 O 直觉 —— 四档速度，四个生活比喻

    大 O 记号描述「数据量翻倍时，工作量怎么涨」。不用背公式，记住四个生活画面就够用：

    跳到书第 P 页
    O(1)
    常数：书多厚都一步到位 · data[3]
    查字典
    O(log n)
    对数：每次砍一半 · 二分查找
    全班点名
    O(n)
    线性：一个一个来 · 一重循环
    两两握手
    O(n²)
    平方：人人都要配对 · 嵌套双循环

    感受一下 n = 1000 时的差距：

    O(1) → 1 步 （跳页） O(log n) → 约 10 步 （查字典：2¹⁰ ≈ 1024） O(n) → 1000 步 （点名） O(n²) → 1000000 步 （握手：1000 × 1000）

    看到嵌套双循环就条件反射想到「两两握手」，看到每次砍一半就想到「查字典」——这就是算法师的直觉。
