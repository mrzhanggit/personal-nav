    • 1类是图纸，对象是实例

    前面 15 课，我们用的都是 Python 自带的"种族"：int、str、list、dict……进阶秘境第一课，你要学会创造自己的种族。

    关键比喻来了：类（class）是图纸，对象（object）是照着图纸造出来的实物。游戏里"幻兽"是一个种族设定（图纸），而你抓的那只"小白"是一只具体的幻兽（实例）——图纸只有一张，实例可以造无限多只。

    class Pet:
    📋 图纸 · 类
    · 只有一份，静静躺在代码里
    · 规定"每只宠物有哪些属性"
    · 规定"宠物会哪些动作（方法）"
    ➜ 造 ➜
    Pet("小白") / Pet("小黑")
    🐾 实物 · 实例
    · 可以造很多只，各自独立
    · 小白有小白的名字和 HP
    · 小黑有小黑的名字和 HP

    把图纸写出来，只需要 class 关键字：

    class Pet: # 定义一个类，注意行尾的冒号 def __init__(self, name): # 构造方法：出生登记处（下一步细讲） self.name = name # 给这只宠物登记名字 pet = Pet("小白") # 实例化：照着图纸造一只，取名小白 print(pet.name) # 用 点号 访问它的属性
    小白

    三个术语对齐一下：定义类（写 class Pet:）→ 实例化（执行 Pet("小白")，也叫"创建对象"）→ 实例/对象（造出来的 pet）。类名习惯用大驼峰命名：Pet、PlayerAccount——一看就知道是个类。

    2__init__ 构造方法 —— 出生登记处

    __init__（init 是 initialize"初始化"的缩写，前后各两条下划线）会在实例化的那一刻自动执行，专门负责给新生的实例登记属性。眼见为实——

    class Pet: def __init__(self, name): print(name, "出生了！") # 出生时喊一嗓子 print("—— 召唤之前 ——") pet = Pet("小白") # 实例化：__init__ 此刻自动执行！ print("—— 召唤之后 ——")
    —— 召唤之前 —— 小白 出生了！ —— 召唤之后 ——

    看到了吗？"小白 出生了！"出现在两句之间——没人手动调用它，是 Pet("小白") 这一行触发的。实例化时你传的 "小白"，会作为参数传给 __init__ 的 name 形参。

    ⚠️ 常见误区：__init__ 不是你调用的，是 Python 替你调用的。写 pet.__init__() 手动调用反而是错误用法；初始化逻辑永远只写在定义里，让每一次实例化都自动走一遍。

    3self 是谁 —— 指向实例自身

    所有方法的第一个参数永远是 self，它指向当前这个实例自己。同一个方法要伺候千千万万只宠物，靠什么知道"现在轮到谁"？靠 self。

    class Pet: def __init__(self, name): self.name = name # self.name = "这只宠物"的名字 def eat(self): # 方法：每个都带 self self.hp = 100 # 只改"这只宠物"的 HP a = Pet("小白") b = Pet("小黑") print(a.name, b.name)
    小白 小黑

    调用方法时，a.eat() 其实等价于 Pet.eat(a)——Python 悄悄把 a 塞给了 self！这就是为什么方法定义必须写 self、调用时却不用传它：

    class Pet: def __init__(self, name): self.name = name self.hp = 100 def eat(self): self.hp = self.hp + 10 a = Pet("小白") a.eat() # 等价于 Pet.eat(a)，self 接住了 a print(a.hp)
    110

    🧠 记忆口诀：定义写 self，调用不用传；点号前是谁，self 就是谁。忘了写 self 会怎样？预言机第 5 题会给你看"惨案现场"。

    4实例属性 vs 类属性 —— 一人一份 vs 全族共享

    两种属性存放位置不同、归属不同：

    ① 实例属性：写在 self.xxx = 后面，每个实例各自一份——小白的 HP、小黑的名字，互不相干；

    ② 类属性：直接写在 class 里面（不在任何方法里），全体实例共享一份——适合放"全族通用的设定"，比如种族名。

    class Pet: species = "幻兽" # 类属性：写在方法外面，全族共享 def __init__(self, name): self.name = name # 实例属性：写在 self. 后面，每只一份 a = Pet("小白") b = Pet("小黑") print(a.species, b.species) # 两只都能查到种族 b.species = "神兽" # 给 b 单独赋值：给 b 自己发了一张 print(a.species, b.species) # a 不受影响！ print(Pet.species) # 类属性本体还在类身上
    幻兽 幻兽 幻兽 神兽 幻兽

    ⚠️ 高频考点：实例属性和类属性同名时，实例属性优先。查 b.species 时 Python 先翻 b 自己的口袋（实例属性），翻到就不再看类了；而 a 的口袋里没有 species，才去类身上找到 "幻兽"。给 b 赋值永远只是给 b 自己发新卡片，绝不会改动类属性本体。

    5多实例互不干扰 & 为什么需要类

    多只宠物、各自的数据、互不干扰——这是实例属性的天性，也是本课实验室的核心看点：

    class Pet: def __init__(self, name): self.name = name self.hp = 100 def take_damage(self): self.hp = self.hp - 30 a = Pet("小白") b = Pet("小黑") a.take_damage() a.take_damage() # 只有小白挨打 print("小白 HP:", a.hp) print("小黑 HP:", b.hp)
    小白 HP: 40 小黑 HP: 100

    小白被打掉 60 点血，小黑毫发无伤——每个实例的属性都存在自己身上，改 a 不碰 b。

    那为什么需要类？想想没有类的日子：数据（一堆字典）和行为（一堆函数）各管各的，函数一多就乱——

    # 没有类：数据和行为分离，像散装的零件 def eat(pet): pet["hp"] = pet["hp"] + 10 # 每个函数都要把字典传来传去 pet1 = {"name": "小白", "hp": 80} eat(pet1) print(pet1["name"], pet1["hp"])
    小白 90

    有了类，数据和行为打包在同一个图纸里：属性（数据）+ 方法（行为）+ 一份图纸批量制造——这叫面向对象编程（OOP）。宠物多到 100 只时，字典方案要写 100 套键名不出错，而类方案只是 Pet("名字") 一行接一行。下一课的"继承"还会让图纸之间互相传承——OOP 的爽点才刚开始。

    6🎮 实验室 · 宠物养成系统

    左边是 Pet 类的图纸（Python 定义），右边是照图纸造出来的实例卡片。点击卡片上的按钮，等价的 Python 方法就会执行——左侧代码会高亮当前执行到的方法。先召唤第二只宠物，再分别操作它们，亲眼验证「所有宠物共享图纸、各自有独立属性」。

    class Pet: species = "幻兽" # 类属性：全族共享一份 def __init__(self, name): # 出生登记处：实例化时自动执行 self.name = name # ↓ 以下全是实例属性：每只一份 self.hp = 100 self.mood = "开心" self.level = 1 self.exp = 0 def eat(self): # 喂食：self 就是点号前那只 self.hp = min(100, self.hp + 10) def play(self): # 玩耍：心情变兴奋，经验 +5 self.mood = "兴奋" self.exp = self.exp + 5 if self.exp >= 10: # 经验攒满 10 → 升 1 级 self.level = self.level + 1 self.exp = self.exp - 10 def sleep(self): # 睡觉：回满血，心情安静 self.hp = 100 self.mood = "安静"
    🔍 观察要点：① 所有卡片都写着同样的种族 幻兽（类属性，共享图纸）；② 每只宠物的 HP / 心情 / 等级 / 经验各改各的，怎么喂小白都喂不到小黑肚子里（实例属性，独立存放）；③ 每次操作，左侧高亮的方法里那句 self，指的就是你点的那张卡片。（本页用内存 JS 对象模拟实例，刷新后宠物回到出生状态）
