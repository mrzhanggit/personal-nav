## 四、自定义域名绑定（可选）

如果您买了域名（比如 `example.com`），两边绑定方式：

### GitHub Pages 绑定 `nav.example.com`

1. 在域名 DNS 里添加记录：

   | 类型 | 主机记录 | 记录值 |
   |---|---|---|
   | CNAME | nav | `mrzhanggit.github.io` |

2. 仓库页 → Settings → Pages → Custom domain 填 `nav.example.com` → Save
3. 等 DNS 生效（几分钟到几小时）后勾选 Enforce HTTPS

### Cloudflare Pages 绑定 `rwh.example.com`

1. **如果域名 DNS 托管在 Cloudflare**（推荐，转入免费）：Pages 项目 → Custom domains → 添加 `rwh.example.com`，CNAME 自动配好，零操作
2. **如果 DNS 在别处**：在原 DNS 服务商添加 `CNAME rwh → rwh-quotes.pages.dev`，再到 Cloudflare Pages 项目里添加自定义域名

### 绑定后同步改导航

在 `links.json` 里把对应条目的 `url` 换成自定义域名（或 pages.dev / github.io 地址），两份（根目录 + dist）都要改。

## 五、跨平台资源引用规则（黄金法则）

两边平台、两种 URL 结构（GitHub Pages 是子路径 `/personal-nav/`，Cloudflare 是根路径），路径处理记住三条：

1. **站内引用一律相对路径**——不要用 `/` 开头
   - ✅ `href="timeline/rome/index.html"`
   - ✅ `src="./assets/pic.png"`
   - ❌ `href="/timeline/rome/index.html"`（GitHub Pages 子路径下会 404）
   - 已全站检查过现有页面：零违规 ✓

2. **跨站链接一律完整 URL**——从导航页跳到 RWH、资产看板等，写完整 `https://...`，与托管平台无关

3. **`links.json` 是导航唯一数据源**，维护约定：
   - 根目录 `links.json` 与 `dist/links.json` 必须同步修改（内容应保持一致）
   - `url` 字段：站内条目用相对路径，外部条目用完整 URL
   - 改完 commit + push 即自动发布 GitHub Pages

4. **CDN / 外链资源**（字体、JS 库）不受平台影响，可正常使用（现有 japan-history.html 引了外部 CDN，两边都能跑）
